# ADR-0005: Minecraft 场景数据接入与 TA 参数 DSL

- **状态**: Accepted (2026-07-26，所有者裁决 D1–D4)
- **决策者**: 项目所有者 (Chilliziehen)、Claude
- **关系**: 把 T0「编译期可确定者不在执行期确定」与 ADR-0003「执行期微内核」落到
  「场景数据 → 渲染参数」这条链路；不放宽执行期零图解释。不修改 ADR-0004 的
  presentation 所有权(该问题独立待裁)。

---

## Context

TA 在 Editor 中编写渲染管线时需要访问场景数据(世界时间、相机位置、太阳角度等)，
并对其做运算；也需要访问**我们无法预先枚举**的第三方模组数据(如风力/风向)。

### Minecraft 26.2 现状(2026-07-26 反编译实测)

原版已具备一套注册表驱动的环境属性系统，本 ADR 的全部结论建立在这一实测之上：

- `BuiltInRegistries.ENVIRONMENT_ATTRIBUTE`：原版注册 48 个属性，命名空间分
  `visual/*`(雾色、雾距、天空色、太阳角、月相、星角、星亮度、云高、环境光色…)、
  `gameplay/*`、`audio/*`。
- `EnvironmentAttribute<Value>`：携带 `AttributeType<Value>`、默认值、取值范围，
  以及 `syncable` / `positional` / `spatiallyInterpolated` 标志。
- `BuiltInRegistries.ATTRIBUTE_TYPE`：值类型本身也是注册表(BOOLEAN、FLOAT、
  ANGLE_DEGREES、RGB_COLOR、ARGB_COLOR、INTEGER、MOON_PHASE…)，Codec 驱动，
  因此属性值可由数据包定义。
- `EnvironmentAttributeProbe`：每 tick 对玩家周围生物群系做高斯加权采样得到空间
  混合值，`getValue(attribute, partialTicks)` 再做 partial-tick 插值；渲染侧经
  `camera.attributeProbe()` 获得。
- `WeatherAttributes`：天气不是独立注册表，而是以 `EnvironmentAttributeMap`
  modifier 层(`BLEND_TO_GRAY` / `ALPHA_BLEND` 等)覆写基础属性。

**关键推论**：层叠、生物群系混合与时间插值全部由原版解决，最终值只需一次
`probe.getValue()` 调用即可获得。遵循该注册机制的第三方模组，其数据可被我们
枚举注册表自动发现，无需逐模组硬编码。

### 风险

若允许 TA 在每个 pass 写不受限脚本，逐帧解释会重新进入热路径，T0 与 ADR-0003 的
保证随之失效；同时无法阻止心怀恶意或思路不清的 TA 破坏游戏进程稳定性。

## Decision

### D1. 数据源分级：MVP 只做 Tier 1（注册表自动发现）

- **Tier 1**：装载期枚举 `ENVIRONMENT_ATTRIBUTE` 与 `ATTRIBUTE_TYPE`，导出机器可读的
  **能力清单**(属性 id、值类型、默认值、取值范围、是否空间插值、是否同步)，Editor
  以此作为数据调色板。清单另含我方内建源(相机矩阵、帧计数、视口尺寸、partial tick、
  渲染分辨率)。
- 遵循原版注册机制的第三方模组数据**自动出现在清单中**；我方不维护模组白名单。
- 属性取值统一经 `EnvironmentAttributeProbe`，不自行复现层叠/插值逻辑。
- Tier 2(非注册表数据源)推迟，见 D5。

### D2. TA 脚本语言：自研受限 DSL

采用自研受限 DSL，由 Core 既有 ASM 后端在**烘焙期**编译为直线字节码。

- **理由(所有者裁决)**：控制权。通用嵌入式语言无法在结构上保证热路径零分配、零装箱、
  零反射，也无法阻止 TA 破坏游戏程序。
- DSL 表达力上限：仅声明过的具名输入、值类型(float/vec2-4/mat4/int/bool)、纯表达式与
  语句、无堆对象、无无界循环、除声明数据源外无宿主 API 访问。
- 零分配是**构造上的保证**，不是约定。
- 已评估并否决的替代方案：LuaJ 等解释器(逐帧解释，直接违背 ADR-0003)；GraalVM
  polyglot(体量与预热开销，确定性不足)；Janino / Java 子集(烘焙期编译可行、性能可
  接受，但表达力过宽，防呆能力不足以满足本条的控制权诉求)。

### D3. TA 逻辑时间域：MVP 只做 A 类（参数计算）

三个时间域必须在创作模型中显式区分，Editor 不得提供跨域的通用脚本框：

| 时间域 | 内容 | 允许开销 |
| ------ | ---- | -------- |
| 烘焙期 | 图 + DSL → 字节码 | 任意 |
| 装载期 | 材质化、预录命令缓冲、**一次性解析数据源** | 一次性，可重入 |
| 执行期 | 只写 frame-slot 参数 + O(1) 选择预录缓冲 | 零分配、零反射、零解释 |

- **A 类 参数计算**：每帧执行，读取声明过的数据源，写入 frame-slot 参数块的固定偏移。
  **MVP 范围**。
- **B 类 图结构决策**：推迟，见 D5。
- **C 类 逐 draw / 逐物体逻辑**：Java 侧**永久禁止**；此类需求下沉 GPU
  (compute + indirect draw)。

### D4. 参数块布局编译期固定

Editor 声明参数块 schema，编译器分配偏移，DSL 编译为向常量偏移的 store。与 §9 BECS
定长表同一原则；执行期不得有布局查表。

### D5. 明确推迟项（记录，不实现）

以下两项**已明确推迟出 MVP，但不是放弃**，记录于此以免后续被当作未考虑过的缺口。

#### D5.1 Tier 2 外部声明数据源

用于不走原版注册表的模组数据(例如仅暴露静态方法的老式模组)。

设计草案：TA 在 Editor 声明 `{类名, 成员名, 签名, 语义类型}`；**装载期解析一次**，
生成字节码中为直接调用(如 `INVOKESTATIC`)，执行期零反射。源缺失时在装载期决议为
声明的默认值并记入 failure context——**不得产生每帧分支**。

落地前需先解决：类型安全校验、缺失降级策略、ClassLoader 可见性规则、第三方 API 的
线程安全契约(须假定非线程安全)。

#### D5.2 B 类 图结构决策

例如「下雨时启用雨幕 pass」。这是架构演进中**明确要做的方向**。

两种可接受的实现路径：(a) 烘焙期编出全部变体，执行期 O(1) 选择；(b) 结构变化作为
**装载期重编事件**处理。逐帧结构决策在任何路径下均禁止。

落地前需先解决：变体组合爆炸的控制(与 §3.3 编译期开关维度对齐)、重编触发时机与
generation 退休策略。

在 D5.2 落地前，昼夜/天气一类切换由美术在图中预先连好分支、以 A 类参数做混合表达。

### D6. 线程约束

`EnvironmentAttributeProbe` 挂在相机上，全部 Tier 1 取值必须在客户端/渲染线程完成。
数据源契约须写明该约束。

## Consequences

- Editor 的数据调色板由运行期注册表生成，不再是我方维护的清单；Editor 必须接受
  **能力清单**作为输入。该清单是一种新的产出物，其命名与格式需按 §8 登记。
- 能力清单需要一条导出链路：`Mod` 枚举注册表 → `Core` 序列化 → Editor 消费。
  `Mod` 只做枚举与转发，不含类型语义(§ 模块边界)。
- DSL 是 Core 中的新编译前端(文法、类型检查、ASM 后端)，适用 §4 覆盖率门槛。
- 原版属性值类型需映射进 DSL 类型系统；打包类型(如 `RGB_COLOR` 在线上是 int、语义是
  颜色)的映射必须显式，不得隐式当作整数运算。
- 图若引用了后续 MC 版本移除的 Tier 1 属性，将在**装载期**以具名属性缺失失败，不会
  静默出错。
- 反编译所得 MC 源码仅作本地参考，置于已被 gitignore 的 `ref/`；任何 MC 源码不得进入
  版本库或被再分发。

## Open

- DSL 文法细节与内建函数集合。
- Tier 1 属性在 MC 版本升级中被移除时，是否需要与 D5.1 一致的降级策略。
- 本 ADR 不触及 presentation 所有权(Minecraft-hosted 与 standalone 的取舍)，该问题
  独立待裁。
